# Working in this repository

Sphinx + MyST technical manual for **FlexiBowl**, published automatically to
https://flexibowl-docs.flexibowl.com.

## Layout

- `sources/` — the manual. Edit here.
- `build/` — generated HTML. **Never hand-edit**; regenerated by `build_manual.bat`.
- `tools/manual_publisher/` — the build pipeline.
- `tools/ci/` — deployment tooling (see Deployment below).

## Media

- Images are capped at 2560 px wide by the build. Don't commit raw CAD exports
  or full-resolution photos; shrink anything over a few MB first.
- Video, GIF, PDF and archives route through Git LFS automatically via
  `.gitattributes`. Install Git LFS before committing media.
- CI rejects any tracked file over 10 MB that isn't in LFS.

This repo hit 1.48 GB on GitHub from 200 MP CAD exports and 36 GB of
crashed-build scratch dirs being committed. Don't repeat it.

## Never commit

- `.tmp_manual_build_*/` — scratch dirs left by interrupted builds. Gitignored;
  delete on sight, they can be tens of GB.
- `.makai/`, `DEPLOY_SETUP.md` — internal infrastructure notes. Gitignored.

## Deployment

- Pushing to `main` **deploys to production** within 1–2 minutes.
- Deploy infrastructure is owned by Makai Labs, not ARS — don't change without
  asking: `Dockerfile`, `nginx.conf`, `.dockerignore`, `.gitattributes`,
  `.github/workflows/**`, `tools/ci/**`.

## Sibling repository

`FlexiVision_One_Documentation` is the companion manual, deployed independently
to its own subdomain. It shares tooling and conventions with this repo — the
rules above apply there too, and a change to shared tooling usually belongs in
both.
